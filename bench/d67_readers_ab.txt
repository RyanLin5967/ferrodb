=== READING ================================================================================
TWO QUESTIONS, TWO ANSWERS.

(1) DOES THE READER DRAIN COST THE WRITE PATH ANYTHING? NO. Pre-registered as a real possible
    outcome, and it came back null:
        readers   0 -> 40.4 merges/sec, 0 reads
        readers   1 -> 40.8 merges/sec, 24,218 reads
        readers   4 -> 43.2 merges/sec, 100,071 reads
    A hundred thousand lock-free reads cost the write path NOTHING — throughput drifted UP, within
    noise. So `drain_readers`' SeqCst store to `writer_active` and its second global mutex are free
    in practice at this scale, the D51 concern about a shared-word write on the hot path does not
    bite here, and the wall is ONE thing (the whole-statement critical section) rather than two.
    It also shows D58/D59's lock-free read path doing exactly its job: reads and writes coexist.

(2) HOW MUCH IS ON THE TABLE? 47x.
        16 threads, ONE ServerContext (the real system) ....  12.5 merges/sec
        16 threads, 16 ServerContexts (no shared structure)   593.5 merges/sec
    **47.5x.** That is what the global catalog lock costs at 16 threads.

    ⚠ AND IT IS NOT AN IDEALISED NUMBER. The private arm reaches only 3.7x over a single shared
    thread (593.5 against 159.6) because this box is loaded (load 23) and each private database
    still pays its own WAL and its own fsyncs. So the 47x is the gap to what THIS MACHINE, THIS
    CODE and THIS LOAD already achieve once the sharing is removed — not to a theoretical peak.

⛔ THE CEILING IS A BOUND, NOT A PROPOSAL, and the distinction is the whole reason it was run.
Sixteen private databases are not one database: nothing that must stay consistent ACROSS agents
can be built that way, and branch-per-agent is precisely about agents sharing a base. Quoting
593.5 as an achievable ferrodb number would be dishonest. Quoting it as "the wall costs 47x" is
what it supports.

WHAT THIS DOES TO THE BAR: the project's rule is that a change earns a pass only at a
complexity-class change or >=10x. Removing this wall is bounded at 47x on a measurement that
already exists, which clears the bar by a factor of nearly five — and unlike a micro-optimisation,
the bound was established BEFORE any mechanism was proposed, so it cannot be reverse-engineered to
flatter one.
