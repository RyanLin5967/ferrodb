Question: is cow::diff::diff O(delta · log_m N), or O(N) with a skip counter
bolted on? delta is held at exactly 4 modified rows; N is the only axis.

Instruments:
  new_visited   cow::diff::DiffStats::visited — nodes whose payload was decoded
                by the synchronised descent. THE CLAIM.
  skip_pid      skips won by PAGE IDENTITY alone — free, exact in this store, no
                hashing. Within one lineage an unchanged subtree IS the same page.
  skip_cid      skips that needed the supplied NodeIdentity, i.e. two DISTINCT
                pages holding the same rows. Only this tier can be wrong, and
                only a content digest can win it. Zero means the digest
                contributed nothing on this workload — see the note below.
  skipped nodes exact nodes under the skipped subtrees (an audit walk, run after
                the diff and not part of its cost).
  old_touched   walk_pages(base)+walk_pages(head) — what CowTree::diff must
                enumerate before it can prune. THE CONTROL.
  old_examined  CowTree::diff's own pages_examined. It reports the DECODE half
                only, which is why it looks cheap while old_touched tracks N.

All three paths were asserted to return the same 4 Modified rows at every N;
a row that did not would have aborted the run rather than been banked.

WHICH TIER DID THE WORK: skip_cid is 0 at every N, for BOTH providers.
Every skip here was won by page identity alone — a u32 compare, no hashing,
no warm-up. On this workload (one lineage, a fork plus four overwrites) the
content digest contributed NOTHING, and the curve above would be unchanged
if it did not exist. That is the honest reading and it follows from the
store's design: within a lineage an unchanged subtree IS the same page, so
there is nothing left for a digest to find. A content id earns its cost only
where page ids CANNOT match — two branches that never shared a page, or a
subtree rewritten to identical content. Neither occurs here. Anyone quoting
this table as evidence FOR content addressing would be quoting it backwards.
