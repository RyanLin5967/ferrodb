VERDICT: REFUSE. The mechanism is built and tested; it is NOT adopted and NOT wired into
any write path. The deciding result is not that dedup wins too little -- it is that the
frontier's mechanism CANNOT FIRE IN THIS ENGINE AT ALL, and that this is deliberate:

  There is not one byte-identical WHOLE page in any configuration measured below, including
  dup_frac = 1.00 where every branch writes byte-identical ROWS. ForkBase dedups because its
  chunks carry no per-owner identity; ferrodb's pages carry birth_epoch and arena_id exactly
  so the epoch-interval reaper can free them without a global liveness question.
  THE SAME 24 BYTES THAT MAKE DEDUP IMPOSSIBLE ARE WHAT MAKE RECLAMATION CHEAP.

  Payload-level dedup -- keying on page[24..] instead of the whole page -- is the only form
  that could ever pay here, and it is refused too. It buys a workload-CONDITIONAL 10-30% and
  costs refcounts; refcounts reintroduce the global liveness question that src/cow/mod.rs
  lists as a deliberate non-goal ('this is why Dolt needs copying mark-and-sweep GC'), which
  makes a chunk-GC row live that is otherwise dead. Reopening a solved reclamation path for
  a conditional 10-30% is the wrong trade. Written down so it is not rediscovered.

TWO RESULTS, and the first one is the one that matters most:

(a) 'distinct pages' EQUALS 'distinct whole' in every single row, including dup_frac = 1.00
    where every branch writes byte-identical rows. There is not one byte-identical WHOLE
    page anywhere in this store. cow::page_header puts {birth_epoch, arena_id, crc32} in

    pages that differ. ForkBase's mechanism as stated -- identical content anywhere is one

(b) CoW has already banked the large saving. 'page refs' is what these branches would cost

A saving percentage is a ratio and a ratio cannot tell a constant from a complexity class.
The sweep exists so the SLOPE can be fitted -- pages per additional branch:

  series                              pages/branch  fixed pages
  stored today, dup=0.00                    14.000        426.0
  stored today, dup=0.50                    14.000        426.0
  stored today, dup=1.00                    14.000        426.0

  deduped,      dup=0.50                    10.000        430.0
  deduped,      dup=1.00                     6.000        434.0

Read the slopes, not the percentages. Dedup does not change the complexity class: both
series are linear in the branch count. What it changes is the COEFFICIENT, and only when
branches write identical content. At dup_frac = 0.00 the two slopes are the same number.

There is also a FLOOR that dedup can never go below, visible in the deduped slope at
dup_frac = 1.00: it is not zero. Every branch keeps at least its own tree spine. Internal
nodes hold child PageIds, which differ per branch by construction, so the spine can never
be byte-identical across branches no matter how identical the data is.

-- WHAT ADOPTING THIS WOULD COST, which is why it is not wired in --

src/cow/mod.rs lists 'No content addressing' and 'No reference counts' as deliberate
non-goals, each with a stated reason (btrfs's backref explosion; Dolt needing copying
mark-and-sweep GC). This is not an oversight to be corrected -- it is load-bearing:

  A deduped page holds ONE arena_id and ONE birth_epoch but is referenced by TWO branches.
  Liveness here is branch::record::reclaimable, an epoch-interval rule stated per OWNER.
  It cannot answer for a page with two owners. Adopting dedup means retiring that rule for
  shared pages and running refcounts instead -- across the reaper, the pending-free log and
  free_arena's O(1) whole-extent path, which exists precisely to avoid per-page analysis.

And the cheaper alternative is already measured, in the table above. Content that is
identical across branches BY CONSTRUCTION can be written to the trunk BEFORE forking, where
CoW shares it for free: that is exactly what the 'cow saves' column is, and it needs no
index, no refcounts and no change to liveness. Dedup's real remaining case is CONVERGENT
writes -- two branches independently arriving at identical bytes, unknowably in advance.
That case is real. Its magnitude in a production agent workload is NOT measured here, and
this harness cannot measure it: dup_frac is an input, not an observation.

-- WHAT WAS BUILT --

src/cow/dedup.rs: ChunkIndex, a content-addressed index over page payloads with refcounts.
  * ContentId is sha256 truncated to 128 bits, and is treated as a HINT. Every hit compares
    the bytes before sharing; a bucket is a LIST so two payloads that collide keep separate
    pages. Forced with an always-collide hasher, because an unexecuted branch is untested.
  * An increment is provisional until commit(). RefTicket rolls it back on Drop, closing
    the in-process window (?, early return, panic) between raising a refcount and recording
    who owns the reference.
  * A process crash runs no destructor, so provisional increments are journalled and
    recover() rolls back every uncommitted one. Tested with std::mem::forget, which is what
    a dead process looks like to the structure.
  * An over-release is REFUSED, not clamped: a clamp turns the decrement that deletes live
    data into a silent no-op.
  * Allocation happens outside the index lock (the store's arena lock would invert against
    it); the resulting race is closed by re-checking and handing the loser's page back as
    surplus rather than leaking it.

  test result: ok. 14 passed; 0 failed; 0 ignored; 0 measured; 1365 filtered out; finished in 0.00s

  Mutation fire-check -- each guard broken on purpose, and the test that caught it:
    CAUGHT  byte-comparison removed          -> a_content_id_collision_does_not_share_pages
    CAUGHT  recover() made a no-op           -> a_crash_between_the_increment_and_the_record_leaks_nothing
    CAUGHT  over-release clamped not refused -> an_over_release_is_refused_and_changes_nothing
    CAUGHT  Drop rollback removed            -> an_uncommitted_ticket_rolls_its_increment_back_on_drop
    CAUGHT  race re-check skipped            -> a_racing_publisher_makes_the_loser_hand_its_page_back
    CAUGHT  audit ignores a zero refcount    -> the_audit_detects_an_inconsistency_it_is_supposed_to_catch
  Six mutants, six dead. The guards are tested, not merely present. Scripts that produced
  this: the mutation runs are in the commit log, not kept as files -- each one edits
  src/cow/dedup.rs in place, runs one test, and restores the file from HEAD.
