⚠ WHAT THE ANNOUNCEMENT COUNTS DO AND DO NOT SHOW
--------------------------------------------------
The E.6 census (bench/d151_parse_site_result.txt) is a COUNTER, and a counter answers exactly one
question: how many times was `ServerContext::catalog()` taken. It is honest about that and silent
about everything else — it does not show that a removed acquisition changed throughput or latency,
and it says nothing about what any acquisition DID. The same shape bit the d159 lane, where a
mutant that lost every staged fork left six of seven tests green because a counter ratio agreed
with itself. **The functional claim here is carried by the suite above and by
tests/d151_parse_reads_a_refreshed_snapshot.rs — which was fire-checked against a mutant
(bench/d151_firecheck.txt) — not by the count.**

Above, this file says *"`main` moved from 4685d80 to 0bd5c4a DURING the suite"*, and in the report
that accompanied it I wrote that this was a bench-only PUSH landing, prefixed "I assume."
**The gate result is unaffected and the mechanism was wrong.**

  * `origin/main` was `4685d80` throughout and never moved. Verified here:
    `git merge-base --is-ancestor 0bd5c4a origin/main` → false. 0bd5c4a is LOCAL ONLY.
  * `0bd5c4a` is `bank-ebdf002: add the verifier's own SUMMARY.txt — the bank was not
    re-checkable`, held locally and deliberately unpushed so that main's in-flight CI on
    4685d80 would not be cancelled a third time.
  * **Worktrees share one `.git`.** `tools/land-gate.sh` defaults its base to `main`, which is
    the shared LOCAL ref — not `origin/main`, and not a ref private to this worktree. So a
    teammate committing to local main in a different worktree moves the base this gate reads,
    with nothing pushed anywhere.

  ⇒ The [2/3] verdict stands unchanged: `COVERED-NO-CODE` against
    bench/land-ebdf002_certified/{CERTIFICATION.txt,SUMMARY.txt} is correct whether that commit
    is local or remote, because neither file is code.
