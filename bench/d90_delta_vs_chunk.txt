[HERE] 2026-09-21T04:38:09Z at 8be3c8c6fa55
Harness: examples/d90_delta_vs_chunk.rs. 100,000-row table, fixed. r = rows changed,
swept 1 -> 4096 by doubling. Each r: fork a branch, UPDATE exactly r rows scattered
across the key space (i -> 1 + i*7919 mod N, injective), MERGE, count bytes stored.

PRICES ForkBase's own concession, VLDB'18 p.1139 footnote 2: "chunk-based deduplication
is less effective than delta encoding when the deltas are of much smaller size than the
chunks." They deferred the fix to future work in 5.3 and never returned to it. Nobody in
the Noms/Dolt lineage delta-encodes either, and single-row write amplification has never
been published for any of these systems.

THESE ARE COUNTERS, NOT TIMINGS, SO FLEET LOAD DOES NOT AFFECT THEM.
Pages come from a counting Storage injected at DiskManager's existing seam (production
path untouched); WAL bytes from wal::log::fsync_counters(); arena bytes from
storage::atomic_file::atomic_replace_counters(). Integers, identical at load 60 and at
load 0. Taken deliberately WITHOUT the fleet measure lock, at load average ~34 with 13
sibling agents compiling. The check that this is sound is in the data: the ascending and
descending passes reproduce the same page counts to the byte (worst disagreement 1.01x).
The merge ms* column is wall-clock from that loaded box. It is NOT a measurement and must
not be quoted; it is present only to show the sweep did work.
load during: 33.65 34.30 37.44

HOW EACH SINK IS PROVEN LIVE, not merely zero:
A counter reading zero because nothing feeds it is indistinguishable from a real zero,
and the FIRST full run of this sweep reported arena bytes of 0 for all thirteen r values
for exactly that reason -- ArenaPageStore::persist_if_configured is a no-op until
checkpoint_to sets a path, and the harness had never set one. A column of zeros looked
like a finding and was a wiring bug. Two things now prevent that recurring:
  * build() configures the checkpoint path, so the arena sink actually writes;
  * the run prints WHOLE-RUN TOTALS across build, warm-up and both passes, and states
    outright that a sink which is zero for the entire run is NOT WIRED and its per-r
    column is an artefact. This run: WAL 166 fsyncs / 9,160,893 B; arena 111 replaces /
    228,807 B. Both non-zero, so both are live.

A MERGE THAT PUBLISHED NOTHING IS REFUSED, AND THE REFUSAL IS PROVEN TO FIRE:
MergeReport::applied_to_target reports true for an EMPTY changeset. Such a merge costs
the one page every merge costs, so it would have produced exactly the flat line this run
looks for -- the one result the harness must not be able to manufacture. Every cycle
therefore reads its last written row back through an ordinary SELECT against the trunk,
outside any agent session and after the counters are read, and refuses to report bytes
unless the trunk holds the value the branch wrote. Forced to fire with D90_FIRECHECK=1,
which forks and merges while staging nothing:
    r=64: MERGE reported applied, but trunk row id=3898 reads Some(Integer(27286)),
          not Integer(64). The merge published nothing this sweep can price.
          Refusing to report its bytes.
    REFUSED: a warm-up cycle did not complete
    exit 1
27286 is 3898*7, the row's build-time value: the merge genuinely moved nothing while
reporting success. Without the flag the same binary completes the sweep, so the guard
does not fire spuriously.

TWO MORE GUARDS, both of which caught a real defect in this harness:
  * Sessions use Session::with_runtime, never Session::new(). Session::new() builds its
    own AgentRuntime (storage: None, in-memory catalog, its own provenance store), and
    agent_sql::dispatch.rs:407 dispatches every agent statement through session.runtime
    -- so the first three attempts measured an in-memory stub with no arena and no CoW
    pages while reporting branch=1@g0 prov=prov1 every cycle.
  * assert_fresh_branches reads the branch out of SessionStarted and refuses a repeat,
    because a fixed agent identity makes every cycle re-enter one branch and report the
    accumulated cost of its predecessors.
