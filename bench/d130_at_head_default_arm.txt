D130 — IS THE GROUP-COMMIT BATCH SET BY THE THREAD COUNT? MODE=pgwire.

⚠ LAYER: the shipped pgwire server over a real TCP socket, one client connection per
  thread or per fork, forks issued as `BEGIN AGENT SESSION`. Locks held, outermost
  first: `ServerContext::catalog()` -> `AgentRuntime` state -> `TableBranchCatalog`'s
  `logical`. E.6 measured that this is NOT the same experiment as MODE=direct, which
  is `examples/fork_concurrency.rs`. Amendment 1 binds each number to its layer.

  f/sync   = forks the server named, divided by fsyncs the catalog issued. A ratio of
             two counters taken by one instrument over one run, so it is load-immune.
  f/sync÷T = the pre-registered discriminator. ≈0.5 flat ⇒ outcome 1 (wake-up race);
             falling in T ⇒ outcome 2 (the batch is not bounded by the threads);
             ≈1.0 ⇒ outcome 3 (the batch already captures everyone).

⛔ NO THROUGHPUT IS REPORTED. Each fork is a TCP round trip and the box is shared;
   a rate from this harness would be a fact about the socket. The counts are the
   evidence.

RUN-ID MODE: distinct  (D130_RUN_ID unset or `distinct` — the default arm)
  Every fork carries `(a<thread>, r<thread>_<iter>)`, a key the provenance
  store has never seen, so `intern` mints a NEW entity on every fork, while
  AgentRuntime's `state` mutex is held. Whether minting one also costs an
  FSYNC depends entirely on WHICH STORE — see PROV STORE below; under the
  default `mem` it does not. D130_RUN_ID=shared removes the mint.
PROV STORE: mem  (D130_PROV unset or `mem` — MemProvenanceStore, the default)
  ⛔ `intern` ISSUES NO FSYNC IN THIS ARM. AgentRuntime::with_storage builds
  MemProvenanceStore; only `with_durable_provenance` installs the store whose
  append_locked calls file.sync_data(), and neither this rig nor
  examples/pgserver.rs calls it — only src/cli/cli.rs does. So `shared` here
  removes an in-memory insert: this is the NEGATIVE CONTROL and must not move
  f/sync. Run D130_PROV=durable for the arm where the fsync exists to remove.
  The arm is pre-registered in this file's header, written before any cell was run.
