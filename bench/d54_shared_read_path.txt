⭐ THE DISCRIMINATOR THAT RULES OUT "THE READ PATH JUST DOES LESS WORK"
----------------------------------------------------------------------
At ONE thread the shared arm is 50600 now against 52187 before -- unchanged, if anything slightly
lower. If the gain were less work per statement it would show at 1T too. It appears only as
threads rise, which is the signature of contention removed rather than work removed. This is the
same discriminator D49 used on turso's ablation, and it holds here for the same reason.

⚠ THE HARNESS WAS CHANGED, DELIBERATELY, AND THAT IS NOT A THUMB ON THE SCALE
----------------------------------------------------------------------------
`exec` in examples/d50_reader_scaling.rs now mirrors pgwire::extended's dispatch: try the shared
read path against a per-thread cached snapshot, fall back to the exclusive lock for anything
try_run_read refuses. Had it kept taking the exclusive lock, arm A would have measured the OLD
path and every number here would be a lie about the change. Both arms run the identical code; the
only difference between them is still whether the ServerContext is shared.

WHAT THIS IS, AND WHAT IT IS NOT
--------------------------------
✅ A SHAPE: "a per-statement acquisition of one process-wide lock serializes readers, and removing
   it lets them scale" -- true of any engine that opens a statement that way. D49 measured the
   same wall in turso (x0.308 at 16T) on an engine nobody here wrote, so the shape is not an
   artifact of ferrodb.
⛔ NOT an absolute comparison with Postgres, SQLite, Dolt or turso. 530352 stmt/s on this box is a
   property of this box and of what ferrodb does NOT do; it is not claimable against anyone.
⛔ NOT a BranchBench result.
