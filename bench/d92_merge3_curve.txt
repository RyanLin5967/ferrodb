WHAT IS BEING CLAIMED

`src/cow/merge3.rs` merges two versions by descending base/ours/theirs together, skipping any
subtree the three agree on. The claim is a COMPLEXITY CLASS: the descent costs O(delta x log N)
page reads, not O(N). Everything below is an operation COUNT, never a wall clock — this box runs a
build fleet, and a count reads the same on a loaded machine as on an idle one.

⚠ WHAT THIS DOES **NOT** LICENSE, AND IT IS THE POINT OF D110
This curve says merge3's descent is cheap. It does NOT say merge3 should be wired into the
production merge. It should not: `MERGE;` issues ZERO PageStore::read_page calls at every table
size (bench/d110_merge_page_reads.txt), so there is no tree on that path whose subtrees merge3
could skip, and the row-level merge is already O(delta · log N). See bench/d110_wire_merge3.md.
A mechanism being fast is not a reason to call it.

THE RESULT IN ONE LINE

    N x256  ->  pages x253.6,  nodes_read x1.44 (contested) / x1.80 (separated).

HOW TO FALSIFY IT

Read the `pages` and `nodes_read` columns. If the merge were O(N) they would grow by the same
factor. `nodes_read` should instead track the tree DEPTH.

⚠ D89 CHANGED THIS FIXTURE, AND THE HARNESS HAD TO BE REPAIRED BEFORE THIS RUN
D89 made leaf boundaries content-defined (`cow::chunker`, "chunk on the key alone"). Two
consequences visible against the pre-D89 banked numbers:
  * The tree is ~4x more pages at every N (63 -> 259 at N=1000), i.e. smaller leaves.
  * The `contested` arm STOPPED BEING CONTESTED. It picked keys `i` and `i+1` and assumed they
    share a leaf; a content-defined boundary can fall between them. `skip_theirs_unchanged` read
    2, 2, 1, 1, 0 across the five sizes where the pre-D89 curve had 0 at every one, so
    `assert_eq!(con_theirs, 0)` failed and the example was RED on main.
The fix (d7a6f64) takes each contested pair OUT OF A LEAF — two entries of one leaf, co-resident
by construction under any chunker — and `arm()` re-reads that premise off the tree and asserts it.
The counter assertion is untouched: the workload was wrong, not the assertion.
⚠ `cdc-boundary` diagnosed the same failure independently on `D89-curve` (94bc632), reaching the
same straddle counts (2,2,1,1,0, summing to 6) against the same rule totals. Two derivations
agreeing on mechanism AND integers. That fix restates the assertion instead; only one should land.

ANTI-VACUITY — three checks, asserted inside the harness so a bad run fails rather than prints:
  1. Every arm asserts `root_fast_path == None`; a root-level O(1) rule would retire the merge and
     the arm would have measured nothing.
  2. Every arm reads back all 8 changed keys plus a 512-point sample of untouched keys.
  3. The skip counters are shown to fire AND not to fire (counter and detector fire-checks below).
