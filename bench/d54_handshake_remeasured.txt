D54 — THE HANDSHAKE, RE-MEASURED. It costs nothing, and here is the careful reading.
===================================================================================
[HERE] this session, 18-core box, release.

The design entry pre-registered this check: "It must not move the D54 numbers materially -- and
if it does, that is a result to report, because a per-thread store that costs throughput would
mean the slot is not really per-thread."

THE HARNESS NOW INCLUDES THE HANDSHAKE, ON PURPOSE. Every shared read does a SeqCst store to its
own slot and a SeqCst load of writer_active. Leaving that out would measure a path the server does
not run, the same way keeping the exclusive lock would have.

ARM A (shared server), 16 readers, ABSOLUTE:
    without the handshake   530352 stmt/s
    with the handshake      534639 stmt/s

⇒ The handshake costs nothing measurable. 534639 against 530352 is inside this box's run-to-run
  spread, and it is the number that matters: the 16-thread total is what the wall was about.

⚠ READ THE MULTIPLIERS CAREFULLY, BECAUSE THEY MOVED AND THE THROUGHPUT DID NOT.
    without: total_vs_1T @16T = 10.481 / 11.305
    with:    total_vs_1T @16T =  9.822 / 10.012
  That difference is in the DENOMINATOR, not the numerator: arm A's 1T baseline went 50600 ->
  54434 in the A->B run. A faster single thread makes the same 16-thread total look like a smaller
  multiple. Reporting only the multiplier here would have said "the handshake cost 6%" when the
  absolute throughput went UP.

⚠ AND THE B->A RUN'S ABSOLUTES ARE ROUGHLY HALF THE A->B RUN'S (270777 vs 534639 at 16T), WITH
  THE CONTROL DROPPING TOO (x12.056 -> x7.655). That is the box, not the change: both arms fell
  together. The ratios are what survive a noisy machine, which is why both orders are run and why
  the control exists. ⛔ In that run arm A (x10.012) came out ABOVE the control (x7.655). That is
  NOT a claim that one shared server beats sixteen independent ones -- it is the control being
  noisy, and saying otherwise would be reading a single number past what it supports.

WHAT THIS LEAVES
----------------
The pre-D54 baseline was FLAT: 52187 -> 46897 stmt/s over 1 -> 16 readers, x0.899. It is now
54434 -> 534639, x9.822, with a correctness handshake that stops a writer freeing pages under a
reader. ✅ SHAPE: "a per-statement process-wide lock serializes readers; removing it lets them
scale, and the exclusion that keeps it safe can be per-thread rather than shared." ⛔ NOT an
absolute comparison with any other database, and NOT a BranchBench result.
