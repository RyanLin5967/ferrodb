THE ERROR IS THE STORE'S OWN, NOT AN INJECTED FAULT: `release_page`'s "double free of page
103" refusal, reached by pre-freeing one page in the extent.

THE FIX IS NOT A WRITE-BACK ON THE ERROR PATH AND NOT A GUARD. `inner` is a live `MutexGuard`,
so a `Drop` guard could not restore into it, and a second write-back is just a second thing a
future `?` can jump over. The vector is mutated IN PLACE and an entry is removed only AFTER the
fallible step that consumes it succeeds (`swap_remove`, O(pending) not O(pending²)). There is
then no window in which the queue is out of shared state ⇒ **the dangerous state is
unrepresentable rather than documented**, and a `?` added here later is safe by construction.

against the broken code and certified the defect.** Which is the whole reason this file exists.
