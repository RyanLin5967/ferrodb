THE DEFECT
  tools/staleness.sh:28 was  base="${2:-agent-isolation}".
  `agent-isolation` was the integration target when the script was written; the project moved to
  `main` and the DEFAULT did not. Measured at fire-check time:
      agent-isolation = f949add     main = 727a8ec     agent-isolation..main = 550 commits
  So a DIRECT call -- `tools/staleness.sh <worktree>`, the form with no base argument -- measured
  every branch against a commit 550 behind the tree it was about to be merged into. It could not
  report "behind" for anything that had branched from main in the last 550 commits. A guard whose
  default cannot fire is worse than no guard: it is a clean bill of health from an instrument
  pointed at the wrong tree.

THE FIX
  -wt="${1:-.}"; base="${2:-agent-isolation}"; head="${3:-HEAD}"
  +wt="${1:-.}"; base="${2:-main}"; head="${3:-HEAD}"
  (plus a comment block above line 28 recording why the default is part of the guard.)
  tools/land-gate.sh is DELIBERATELY UNTOUCHED: :86 already passes the base explicitly
  (`bash tools/staleness.sh . "$BASE_SHA" "$WANT_SHA"`) and is correct.
