THE MECHANISM IN THIS REPORT IS CORRECT AND LANDED. ITS JUSTIFICATION WAS BACKWARDS.

This report argues in several places that a refusal is usually the BENIGN mid-rewrite race
`TableBranchCatalog::upsert` opened — delete-then-insert with no latch across the two — and
that only a rising, non-returning count is a leak. **That premise died with D126**, which
landed 2.5 h before this report was written: `BPlusTreeManager::upsert` is now one in-place
`LeafWrite::Replace` over a single page write, `TableBranchCatalog::upsert` is one line over
it, and there is no window in which a live branch's record is absent to a reader
(`tests/d126_atomic_upsert.rs`; `src/storage/index.rs`, `BPlusTreeManager::upsert`).

⇒ THE TRUE ARGUMENT IS THE OPPOSITE: refusals are now RARE, and that is exactly why each one
  must be reported. Every refusal reaching `ReapOutcome::Refused` is an I/O error or a
  corrupt catalog. The alarm is the FIRST increment, not the derivative.
⇒ As written, the prose would have trained an operator to ignore the signal this row exists
  to raise. The shipped comments and the operator-facing string were rewritten to the
  inverted argument before landing; this file's §2 and §5 keep the retracted wording only so
  the retraction is visible, and both sites are marked [RETRACTED] inline.
⇒ THE OPERATOR MESSAGE DEPENDS ON D126 BEING TRUE. "A count that does not come back down"
  is a leak detector reading a counter, and that cannot work against a noisy baseline. D126
  is what supplies the zero baseline it detects against — the shipped string now says so.
⇒ THE TESTS WERE NOT TOUCHED and did not need to be: they inject `BranchError::Corrupt` via
  `dangling_child` directly (`lease_thread/tests.rs`, `RefusesLiveChildren`), never the dead
  upsert window, so the fixtures already test the post-D126 world.

Everything below this banner is the original 2026-09-22 report, unchanged except for the two
inline [RETRACTED] markers.

4. WHAT THIS RUN ADDED, AND WHY — the trait sweep had no pin
--------------------------------------------------------------------------------
The design entry asserts: "`TwoTierReaper::refused_reaps` counts at the refusal SITE so
`Reaper::reap_expired`, which has no reporter, cannot drop one either." That claim was
argued in a code comment and tested NOWHERE. `reap_expired` returns `Result<Vec<BranchId>>`
— a refusal is by construction not one of the branches it reaped, and there is no room in
the signature for one. It is precisely the call shape where the row's own defect could
survive its own fix.

Added `d127_the_trait_sweep_counts_a_refusal_it_cannot_report` (lease_thread/tests.rs):
two expired branches, one armed with D124's exact `Corrupt`, driven through
`Reaper::reap_expired`. Asserts `refused_reaps()` advanced by exactly 1, that `reaped ==
[doomed]` (so the sweep went PAST the refused branch), that live pages fell, and that the
refused branch sits in `Reaping` with every page intact.

Under M6 it is the only failing test in the whole suite. That is the coverage it adds.

One shape turned out to be UNEXPRESSIBLE, which strengthens the design: "move the counter
into `scan_once`" cannot be written, because `refused_reaps` is a private field of
`TwoTierReaper` and `lease_thread` is a sibling module, not a descendant. The counter can
only live where the refusal is produced.


5. WHY NOT OPTION 1 OR 3, AND WHY NO STRING MATCHING
--------------------------------------------------------------------------------
Option 1 (give `Corrupt` its own `FerroError` variant) is the root fix for L1, and its blast
radius is every `From<BranchError>` site in the crate. It does not by itself fix the defect:
with `Corrupt` separated, `reap_if_still_expired` would still answer `Ok(false)` for both
"not expired" and "some other `Branch` error I decline to decide on", and `scan_once` would
still match it with an empty arm. It narrows the swallow; it does not un-conflate the answer.
NOT DONE HERE and deliberately not smuggled in — it is a separate row with a separate diff.

Option 3 (count and report at the refusal site, leave the type alone) is what `refused_reaps`
does, and it is kept as the FLOOR for callers that have no reporter. As the whole fix it is
insufficient: `scan_once` would still be unable to tell an operator WHICH branch, because it
would still be seeing `false`.

String-matching the message to recover the variant: rejected on sight, per the brief and per
this project's standing rule. A guard that reads wording is walked around by a reword. No
wording is matched anywhere in this diff. The variant is recovered by changing what CARRIES
it — the return type — not by parsing what it printed.
