1. THE DEFECT, RE-VERIFIED FROM SOURCE AT THE BASE COMMIT
--------------------------------------------------------------------------------
Not taken on the design entry's word. Each link re-read at ac2ab26:

  L1  src/branch/types.rs `impl From<BranchError> for FerroError` — `FerroError::Branch(
      e.to_string())`. Blanket. `Corrupt` and `NotFound` become the same variant; the
      distinction survives only inside a string. STILL TRUE AT HEAD — deliberately not
      touched, see §5.
  L2  src/branch/reaper.rs `reap_if_still_expired` — `Err(FerroError::Branch(_)) => Ok(false)`
      on BOTH arms (the `get_raw` re-read and the `reap` itself).
  L3  src/branch/lease_thread.rs `scan_once` — `Ok(false) => {}`. Not pushed to `reaped`,
      not counted in `failed`, never passed to `report`.

⇒ D124's guard text — the sentence naming the parent, the fork epoch and the child — reached
no log, no counter and no operator. The branch keeps its pages (so the safety property D124
was built for holds) and becomes indistinguishable from a healthy one. Under W4 that is an
unbounded leak with no signal.

The conflation is the defect: `Ok(false)` meant BOTH "the lease moved under the sweep, this
branch is fine" AND "the catalog would not answer, I decline to decide".


2. THE FIX
--------------------------------------------------------------------------------
Line numbers are at HEAD 59e1a8f.

  reaper.rs:78    `pub enum ReapOutcome { Reaped | NotExpired | Refused(FerroError) }`,
                  `#[must_use = "a refused reap that nobody looks at is exactly the D127
                  defect"]`. Carries the error, not a marker: the text is the only thing that
                  separates a benign mid-rewrite miss from a genuinely corrupt CHILD entry,
                  and a caller handed a bare count could not print it.
  reaper.rs:782   `reap_if_still_expired` returns `ReapOutcome`, not `bool`.
  reaper.rs:805   the `get_raw` arm  → `Ok(self.refuse(e))`
  reaper.rs:816   the `reap` arm     → `Ok(self.refuse(e))`   ← D124's `Corrupt` arrives here
  reaper.rs:823   `fn refuse(&self, why) -> ReapOutcome` — bumps the counter AND builds the
                  outcome, so no caller can produce a refusal without it being counted.
  reaper.rs:125   `TwoTierReaper::refused_reaps: AtomicU64`, read at :152.
  lease_thread.rs:632  `Ok(ReapOutcome::Refused(why)) => refused.push((branch, why))`
  lease_thread.rs:293  `LeaseStats::refused_branches` — per-branch refusals, summed.
  lease_thread.rs:278  `LeaseStats::refused` RENAMED to `refused_scans` — the whole-scan
                  refusal (no cluster time). A field called `refused` sitting next to
                  `refused_branches` is the same conflation one level up.
  lease_thread.rs:798  `fn refusal_report(&[(BranchId, FerroError)]) -> String`, cap 4 (:786).
                  Free function taking the list, so the operator-facing TEXT is assertable.
                  Count and ids first, reasons capped — the number is what says leak vs race,
                  so it must not be what falls off a truncated line.
  lease_thread.rs `scan_once` takes its reporter as `out: &dyn Fn(String)`. Production passes
                  `&report`; tests pass a collector. Without this seam the only assertable
                  half of a refusal is its counter, and a counter with no reason is most of
                  the defect still standing.
  cli.rs          `refused_branches > 0` added to the "print the lease stats" condition. A
                  session that reaped nothing and refused one branch used to print nothing.

WHAT DID NOT CHANGE — and this is load-bearing. `Refused` is `Ok`-shaped. The sweep absorbs
it and goes to the next candidate, exactly as before. The absorption exists because a branch
whose record is momentarily absent (`upsert` is delete-then-insert with no latch across the
two, so an ordinary `set_root`/`renew_lease` makes a HEALTHY branch miss for a moment) must
not abort the sweep. A fix that traded a silent leak for a reaper that stops on the first
oddity would be worse than the bug. Pinned by mutant M6 below.

4. WHAT THIS RUN ADDED, AND WHY — the trait sweep had no pin
--------------------------------------------------------------------------------
The design entry asserts: "`TwoTierReaper::refused_reaps` counts at the refusal SITE so
`Reaper::reap_expired`, which has no reporter, cannot drop one either." That claim was
argued in a code comment and tested NOWHERE. `reap_expired` returns `Result<Vec<BranchId>>`
— a refusal is by construction not one of the branches it reaped, and there is no room in
the signature for one. It is precisely the call shape where the row's own defect could
survive its own fix.

Added `d127_the_trait_sweep_counts_a_refusal_it_cannot_report` (lease_thread/tests.rs):
two expired branches, one armed with D124's exact `Corrupt`, driven through
`Reaper::reap_expired`. Asserts `refused_reaps()` advanced by exactly 1, that `reaped ==
[doomed]` (so the sweep went PAST the refused branch), that live pages fell, and that the
refused branch sits in `Reaping` with every page intact.

Under M6 it is the only failing test in the whole suite. That is the coverage it adds.

One shape turned out to be UNEXPRESSIBLE, which strengthens the design: "move the counter
into `scan_once`" cannot be written, because `refused_reaps` is a private field of
`TwoTierReaper` and `lease_thread` is a sibling module, not a descendant. The counter can
only live where the refusal is produced.


5. WHY NOT OPTION 1 OR 3, AND WHY NO STRING MATCHING
--------------------------------------------------------------------------------
Option 1 (give `Corrupt` its own `FerroError` variant) is the root fix for L1, and its blast
radius is every `From<BranchError>` site in the crate. It does not by itself fix the defect:
with `Corrupt` separated, `reap_if_still_expired` would still answer `Ok(false)` for both
"not expired" and "some other `Branch` error I decline to decide on", and `scan_once` would
still match it with an empty arm. It narrows the swallow; it does not un-conflate the answer.
NOT DONE HERE and deliberately not smuggled in — it is a separate row with a separate diff.

Option 3 (count and report at the refusal site, leave the type alone) is what `refused_reaps`
does, and it is kept as the FLOOR for callers that have no reporter. As the whole fix it is
insufficient: `scan_once` would still be unable to tell an operator WHICH branch, because it
would still be seeing `false`.

String-matching the message to recover the variant: rejected on sight, per the brief and per
this project's standing rule. A guard that reads wording is walked around by a reword. No
wording is matched anywhere in this diff. The variant is recovered by changing what CARRIES
it — the return type — not by parsing what it printed.

8. FOLLOW-ONS, NOT FIXED HERE, NOT SMUGGLED IN
--------------------------------------------------------------------------------
a) A branch refused at the `reap` arm has already published `Live → Reaping` (`reap` sets
   state before it consults `has_live_children`). `expired_before` is Live-only on both
   catalogs, so that branch is refused ONCE, printed ONCE, and is then invisible to the lease
   thread until `resume_interrupted_reaps` at the next open. Only the `get_raw` arm, which
   leaves the branch Live, produces a per-sweep RATE. Making the sweep re-enter `Reaping`
   records on the tick changes which branches every pass touches and needs its own row and
   its own measurement. Asserted explicitly in the new test rather than left implicit.
b) Option 1 (a real `FerroError::Corrupt`) remains the root fix for the blanket `From`.
