ferrodb branch-scaling benchmark
instrument: std::time::Instant, wall clock, single process, warm cache
trunk: 2000 rows; reads: 2000 samples per configuration

calibration: descent p50 over 2,000 rows = 13.62us, over 40,000 rows = 20.46us (x1.50)
the instrument responds to tree size, so flatness below is a real result.

diverged branches, 10 -> 1000:
  get_row p50 x1.00  (includes a per-call catalog lookup)
  descent p50 x1.00  (tree only, root resolved once)
  fork  p50 x0.69  (below 1.0 is warm-up, not forks getting faster with branch count - do not read it as a speedup)
  pages 64 -> 2044

These are ferrodb's numbers against ITSELF at three branch counts, on this machine.
BranchBench's 5400x figure is that paper's measurement of other systems' overlay pattern;
nothing here reproduces it and none of the above is a comparison against it.

read latency did not degrade materially with branch count.
