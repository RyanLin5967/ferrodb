         page latch: live_scan_misses 0, live_scan_disorder 0.
         So RangeScanner's per-leaf page read latch is NOT load-bearing today,
         for two reasons that are both already true without it:
           1. `frame.data` is assigned wholesale under the frame RwLock, so a
              page read under the frame read lock is already atomic. There is
              no torn page for the page latch to prevent.
           2. `insert_into_latched_leaf` writes the NEW leaf before writing the
              old one, and writing the old leaf is what publishes
              `next -> new_page_id`. The chain never points at an unwritten page.
         Keeping the latch is still defensible as defence-in-depth against (2)
         being reordered back, but it must NOT be described as load-bearing: it
         is an unproven guard and the code should say so.
