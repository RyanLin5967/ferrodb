Linear in the parent's arena count: per-fork 0.213 -> 0.297 ms across 0 -> 2000 arenas,
about 42 ns per arena, and throughput x0.72. fork_child never reads parent.arenas -- the
whole scan is discarded. The most-forked parent in an agent workload is the longest-lived
one, which is the one holding the most arenas, so the cost grows exactly where it hurts.

NOTE THE INSTRUMENT. At parent_arenas=0 the span is EMPTY and the scan is one descent, so
the pre-existing harness could not see this defect at all and a fix would have measured as
noise. FERRODB_PARENT_ARENAS exists to make the blind spot visible.
