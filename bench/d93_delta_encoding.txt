# D93 — delta encoding below the chunk: intra-page deltas for a branch's divergence
#
# ============================================================================
# PART 1 — PRE-REGISTRATION.  Written and committed BEFORE the first measurement.
# Amendments to this section are append-only and must be dated.
# ============================================================================
#
# THE CLAIM UNDER TEST
#
# ferrodb's branch page store shadows a WHOLE 4096-byte page the first time a branch
# touches a page it inherited (src/branch/arena.rs, `cow_page`: the else-branch copies
# `source[PAGE_HEADER_SIZE..]` into a freshly allocated page). An agent branch that
# changes four rows therefore stores four 4096-byte pages to represent tens of bytes of
# divergence. The claim is that an intra-page delta makes the stored bytes PROPORTIONAL
# TO WHAT CHANGED rather than flat at (pages touched) * PAGE_SIZE.
#
# WHAT IS MEASURED
#
# Arm WHOLE  — bytes = PAGE_SIZE * (number of distinct pages the update touched).
#              This is what `cow_page` does today, counted exactly, not modelled.
# Arm DELTA  — bytes = sum of PageDelta::encoded_len() over the same touched pages,
#              where the delta is computed by byte-diffing the real before/after page
#              images produced by the real slotted node encoder in src/cow/node.rs.
#
# Both arms see the SAME page images, produced by the same mutations, in the same run.
# There is no separate build, so the arms cannot diverge by build.
#
# INSTRUMENTS
#
# - stored bytes: exact byte counts from the encoder. Not a timing. Load-independent.
# - read cost:    number of deltas applied to materialise a page, counted by the
#                 materialiser itself. Not a timing. Load-independent.
#   Timings are deliberately NOT the headline: this machine was at load average 35-62
#   on 18 cores with ten agents running, so a wall-clock number here would be noise.
#   Both headline instruments are counters and are unaffected by that.
#
# THE SWEEP
#
# r (rows changed) = 1, 2, 4, 8, ..., 4096 over a table of 16384 rows laid out by the
# real node encoder. Rows to change are chosen by a fixed-seed PRNG so the run is
# reproducible, and the SAME row set is used for both arms.
# Chain depth L = 1..64 successive branch generations each editing the same page.
#
# ============================================================================
# FALSIFIERS — declared before running. Either one firing is a real result.
# ============================================================================
#
# F-A (read cost).  If the number of deltas applied to materialise a page grows with
#      chain length L beyond MAX_CHAIN_DEPTH, the design is WRONG and must be reported
#      as wrong: an unbounded chain turns an O(1) read into O(chain), which is exactly
#      the parent-chain walk that src/branch/mod.rs invariant 2 forbids and that
#      BranchBench measured at up to 4000x read degradation.
#      PASS CONDITION: applied_deltas <= MAX_CHAIN_DEPTH for every L in 1..64.
#      This must be a NON-VACUOUS pass: the run must also report that collapses
#      actually fired (collapses > 0), otherwise the bound was never exercised.
#
# F-B (stored bytes).  If stored bytes do not fall by at least 10x at r=4 versus the
#      whole-page arm, delta encoding does not clear the bar for this workload and
#      that must be stated plainly rather than rescued with a different r.
#      PASS CONDITION: WHOLE_bytes(r=4) / DELTA_bytes(r=4) >= 10.0.
#
# F-C (added, same sitting, before running — honesty guard on my own arm).  A byte-diff
#      of a slotted page is NOT guaranteed small just because few rows changed:
#      `NodeMut::replace_cell_at` writes the new cell into fresh heap space, and when
#      the heap runs out it calls `compact()`, which REWRITES THE WHOLE CELL AREA. A
#      compacting update produces a delta the size of the page. If compaction dominates
#      the sweep, the headline ratio is an artifact of an unrealistically empty page.
#      REPORTING CONDITION: the run must report what fraction of updated pages
#      compacted, and must report the ratio for the compacting regime separately.
#      This falsifier cannot "pass" — it is a disclosure requirement.
#
# WHAT WOULD INVALIDATE THE WHOLE RUN
#
# - Delta sizes computed against synthetic byte arrays rather than real node images.
# - A delta arm allowed to store something larger than a page (it must never: a delta
#   that does not beat the page it encodes is refused and a full page stored instead).
# - The two arms not seeing identical mutations.
#

# F-C (compaction disclosure) — DISCLOSED, and the disclosure is that the sweep never
#      entered the compaction regime at all: the `compact` column is 0 at every one of
#      the 13 points. That is a fact about the sweep's shape, not a clean bill of
#      health. At r=4096, 4096 updates spread over 273 pages average ~15 per page, and
#      a 60-row page absorbs ~39 rewrites before its heap runs out. A branch that
#      concentrates its writes on one page DOES reach compaction, so that regime was
#      measured separately rather than left unmeasured:
#
#        equal-width cells, first compaction       1373 B delta  -> over budget, stored whole
#        after one cell changed width              2552 B delta  -> over budget, stored whole
#
#      Both exceed DELTA_BUDGET = 1018 B, so DeltaStore stores a full page and the
#      delta arm never pretends to a saving it cannot deliver. Neither is page-SIZED
#      (4072 B), which is why the pre-registration's wording is corrected below.
#
# ---------------------------------------------------------------------------
# WHAT THE SLOPE SHOWS
# ---------------------------------------------------------------------------
#
# The result the brief asked for holds: stored bytes became PROPORTIONAL TO r instead
# of flat at r * PAGE_SIZE. The `delta B/row` column stays between 52.9 and 40.9 across
# a 4096x sweep in r — it does not grow — while the whole-page arm saturates at
# 1118208 B (all 274 pages) from r=2048 onward because every page has been touched.
#
# The ratio therefore FALLS as r grows, from 78.8x at r=1 to 6.7x at r=4096, and that
# is the honest shape rather than a disappointment: the whole-page arm cannot get worse
# than the whole table, so once a branch has dirtied every page the two arms converge on
# the ratio of live bytes to page bytes. Delta encoding pays where a branch touches a
# small fraction of the table, which is the agent-branch workload it was aimed at.
#
# THE NUMBER TO QUOTE FOR A LONG-LIVED BRANCH IS NOT 78x.  The chain table shows why.
# A chain must collapse to a full page every 9th generation to hold the read bound, so
# one full cycle stores 8 deltas plus one page: 418 B + 4096 B = 4514 B, against
# 9 * 4096 = 36864 B for whole-page storage. That is 8.2x amortised. The 78x figure is
# a single generation from the fork point; 8.2x is the steady state under the bound that
# makes reads safe. Both are real and they answer different questions.
#

# 2026-09-21. F-C's pre-registered wording — "a compacting update produces a delta the
# size of the page" — went through one wrong correction before reaching its final form.
# Recording both steps, because the intermediate one was a WRONG CORRECTION OF A RIGHT
# CLAIM, which is the same category of error as asserting something false.
#
#   1. Pre-registered: compaction produces a page-sized delta, so it must collapse.
#   2. First measurement said 463 B, comfortably inside the budget. I concluded the
#      pre-registration was FALSE and wrote a test asserting compaction stays a delta,
#      reasoning that `compact()` rewrites cells in slot order descending from
#      PAYLOAD_LEN — the same rule `fill_leaf` used — so equal-width cells land back on
#      the offsets they already occupied and compaction is layout-restoring.
#   3. That 463 B was a FIXTURE DEFECT, not a finding. `value_of` zero-filled its
#      values, and zeros flatter a byte differ twice: a cell written into virgin heap
#      diffs only in its non-zero bytes because `NodeMut::init` zeroes the payload, and
#      a cell shifted by a width change does not diff wherever zeros land on zeros.
#      Real column data is not zeros.
#   4. With high-entropy values the same fixture reports 1373 B — over budget, stored
#      whole. So step 2's correction is REVERSED: the pre-registration's conclusion
#      (compaction collapses) was right all along.
#
#   What remains corrected from the pre-registration is only its magnitude: a compacting
#   delta is 1373-2552 B, not the ~4072 B "size of the page" the original wording
#   claimed. The layout-restoring mechanism from step 2 is still true and is why the
#   equal-width case (1373 B) is cheaper than the width-changed case (2552 B); it just
#   does not make either one cheap enough to store as a delta.
#
# ---------------------------------------------------------------------------
# WHAT THIS RUN DOES NOT ESTABLISH
# ---------------------------------------------------------------------------
#
# - The mechanism is NOT wired into ArenaPageStore::cow_page. Everything above measures
#   src/branch/delta.rs standing alone. Behaviour under the real buffer pool, page
#   checksums and the reaper is unmeasured, and a delta chain interacts with the epoch
#   interval rule in ways this run says nothing about: a base page must not be
#   reclaimable while a delta still points at it.
# - Single-threaded throughout. No concurrent writer or merge is exercised.
# - The delta arm is charged only its encoded bytes. A real implementation needs a
#   container to pack deltas into, and that container's own overhead is not counted
#   here; it would amortise across many deltas but it is not zero.
# - The sweep updates existing rows. Inserts, deletes and node splits are not measured,
#   and a split rewrites both halves, which is a whole-page cost delta encoding cannot
#   avoid.

# A fresh-context agent that had not seen this work was asked one question: can

#   1. `PageDelta::apply` was NOT all-or-nothing. It checked each run's extent inside
#      the write loop, so a refusal left the caller's buffer partly written. Harmless
#      while the only caller applied onto a scratch Vec it dropped on the error — and a
#      corrupted live page frame the moment it is applied in place, which is exactly how
#      it is being wired under `cow_page`. Now validated before any byte moves.

#      — past the 3-page ceiling this file certifies — while naming 8 in its error and
#      actually refusing at 10. So a number this bank reports as bounded at 8 was
#      reachable at 9 by a route `write` happens never to take.
#   3. A doc line claimed `DeltaStore` "refuses to drop a page that something still
#      deltas against". There is no drop method and no pinning of any kind. That line
#      could have been read by a wiring agent as protection that exists.

# THREE LIMITS THE ORIGINAL WRITE-UP UNDERSTATED
# ---------------------------------------------------------------------------
#
# 1. THE HEADLINE IS A FUNCTION OF ROW WIDTH, NOT OF THE MECHANISM. The ratio is
#    roughly PAGE_SIZE divided by what one changed entry costs to encode, so it falls
#    as rows get wider. At this fixture's 24-byte value that is ~79x; the reviewer
#    measured it down to ~14x at a 256-byte value. I did not re-run that sweep myself,
#    so treat the specific figures as unverified — but the DEPENDENCE is arithmetic and
#    is not in doubt, and "77.6x" should never be quoted without the row width it came
#    from. The claim that survives at every width measured is the 10x bar, not the 78x.
# 2. THE DELTA ARM PAYS NO CONTAINER OVERHEAD. `DELTA_HEADER` is 7 bytes and budgets
#    nothing for the 24-byte self-describing page header that any independently
#    reclaimable unit needs. If each delta had to carry one, r=1 would fall from 78.8x
#    to 4096/(52+24) = 53.9x. Deltas packed many-to-a-page would amortise most of that,
#    which is why this is a bound on the concern rather than a correction to the table.
# 3. WRITE COST WAS NOT MEASURED AT ALL. There is a ReadCost and there was no
#    counterpart. `DeltaStore::write` materialises its base (up to 8 delta applications)
#    and then scans a whole 4072-byte payload to diff it — on every write — replacing a
#    single `copy_from_slice`. DeltaStats now counts `write_deltas_applied` and
#    `write_bytes_scanned`, but no sweep of write cost has been run, and the
#    "counters, not timings" argument applies to it exactly as it does to reads.
