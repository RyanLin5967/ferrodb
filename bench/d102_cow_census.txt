D102 — WHICH ARM OF cow_page DOES AN AGENT MERGE TAKE, AND WHAT WOULD IT ENCODE TO?
Harness: examples/d102_cow_census.rs. RAW OUTPUT BELOW IS FROM THE FINAL TREE, on a
20,000-row table, r = rows changed, swept 1 -> 512 by doubling. Each r: fork a branch,
UPDATE exactly r scattered rows (i -> 1 + i*7919 mod N, injective, D90's scatter), MERGE.

WHY THIS EXISTS
D93 measured that an intra-page delta makes a four-row agent merge cost 211 B instead of
16,384 B, and the plan that followed was "wire PageDelta into cow_page". That plan rested
on a premise nobody had measured: that an agent merge reaches the arm of cow_page that
COPIES a whole page at all. cow_page has two arms and a delta can only shrink one of them.

THESE ARE COUNTERS, NOT TIMINGS, so fleet load does not affect them. The two runs below
were taken from separately built binaries minutes apart and agree to the byte.

INSTRUMENT
branch::arena::cow_path_census() — three process-wide integers bumped on the exact two
lines inside cow_page that choose an arm. DELTA B comes from
ArenaPageStore::delta_against_base(), which applies BOTH bounds (MAX_CHAIN_DEPTH = 8,
DELTA_BUDGET = 1018) and answers None when a whole page must be stored instead.

ANTI-VACUITY, and it is proven to fire: every cycle reads its last written row back
through an ordinary SELECT against the trunk, after the counters are read, and refuses to
report unless the trunk holds the value the branch wrote. D102_FIRECHECK=1 forks and
merges while staging nothing; every cycle must then refuse and the process exit non-zero.

⚠ THE HEADLINE RATIO IS OCCUPANCY, NOT BYTES STORED. Each shadow below is ONE page, and
one page is the smallest thing DiskManager writes. D90's headline is
`distinct pages x 4096 + WAL`, so a page whose useful content falls from 4072 B to 52 B
still costs 4096 B and still counts as one page. Occupancy becomes stored bytes only once
several logical pages can share one physical page. Do not quote this as a D90 result.
