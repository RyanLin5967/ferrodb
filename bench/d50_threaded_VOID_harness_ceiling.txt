WHY THIS FILE IS VOID, AND WHY IT IS KEPT ANYWAY
------------------------------------------------
The two arms are INDISTINGUISHABLE — 0.90x to 1.00x apart at every point — and both
plateau together at about x1.35. Arm B gives every client its OWN SERVER on its own
database file, which removes the Mutex<Catalog> entirely. If that lock were the wall,
arm B would separate. It does not move at all.

Two arms that plateau TOGETHER share their ceiling, and the only thing these two arms
share is the client: 16 Python THREADS behind one GIL, doing per-statement wire parsing
in Python bytecode. This repo's own note already names the shape — 'a benchmark harness
can BE the wall: shared state in the timed loop cancels in every comparison and shows
only as a ceiling; A/B it and watch the CONTROL's slope.' The control's slope is the
evidence, and it says the harness.

⛔ So no number below may be quoted as a property of ferrodb. The run is refused, not
caveated. It is committed because the raw artifact of a refused run is what stops the
next pass re-running it, and because the control arm doing its job is the point.

The discriminator is bench/d50_procs.sh: the same clients as separate PROCESSES, so the
GIL is no longer shared. If the total rises, the threaded harness was the ceiling.
