--------------------------------------------------
MUTANT THAT NO LONGER FAILS AT THE SENDER: `read_data_type` mapping tag 4 (BigInt) -> Integer.
With the check, `encode` REFUSED it. With the check deleted, `encode` ACCEPTS it.
WHAT STILL CATCHES THE CLASS: `decode_catalog`'s byte-for-byte identical round trip, on the
receive side, which REFUSED the same frame (measured above, not argued).

⚠ AND THE HONEST COST, because this is not a pure win. Detection MOVES from the sender to the
receiver. The deleted comment's own argument was that the receiver is "the wrong side of the wire
to find out that this node emitted rubbish" — and that argument is still true. What changed is
what it buys: while `write_str` was unchecked the sender's check was the ONLY thing standing
between a truncated name and a durable frame, and now it is not, because the truncation is refused
at the encoder. What remains is a codec-disagreement class that no test exercised, that a mutant
already survived once, and that the sender's check could no longer be made to fire at all — the
`?` above it refuses first.

⇒ So the trade is: a guard that cannot be fired, in exchange for the same class caught one hop
later by a guard that CAN be. This file is the evidence for that trade; it is not claimed to be
free. If a future row wants sender-side detection back, the way to get it is a canonicality test
over `RecKind`'s codec that does not depend on an over-long string to trigger it.

SCOPE OF THIS EXPERIMENT: one mutant, one class. It does not enumerate everything the deleted
check could ever have caught. It shows that the class the check was WRITTEN for is still refused.
