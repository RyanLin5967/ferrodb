S23 fire-check: the streaming cursor's guards, forced to fail on purpose.

A detector that has never fired is not a clean result. Each mutant below was applied to
src/cow/btree.rs, the cursor tests run, and the file restored byte-for-byte (`diff` verified,
last line). What matters is not only THAT each fires but WHICH one fires:

  A, the eager scan, fails ONLY the page-count test. Both correctness tests pass it happily --
  same rows, same order, same bounds. That is exactly why the page counter has to exist: a
  revert to the Theta(table) `Vec` is invisible to every other assertion in this suite.

  B and C, the two off-by-one bounds mutants, fail ONLY the reference-map test and leave the
  page count alone, so the two guards are independent rather than one guard counted twice.

  D is the one that changed the code. Sampling a leaf's type and its bytes under two separate
  read guards is weaker than what the eager scan guaranteed, and on the first run of this file
  ALL 26 TESTS PASSED IT. The property lives inside the buffer-pool frame lock, which nothing in
  `PageStore` exposes, so no test here can see it -- and a concurrency test for it would be a
  detector that cannot be forced to fire, which is worse than none. So `advance_leaf` now drops
  the page handle at the end of the guard's block, and the mutant stops being a wrong program
  and starts being one that does not compile. That is the result recorded below.
