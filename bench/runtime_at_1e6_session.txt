S15 phase 2: N agent sessions opened through the RUNTIME, all held open.

**Which function, exactly.** The bulk loop calls `AgentRuntime::begin_session_as` — the
body `BEGIN AGENT SESSION` reaches through `run_agent_stmt`, NOT the catalog's `fork`.
It is called directly rather than through the scanner because the statement path needs
`&mut Catalog` and so cannot be driven from 64 threads, and a SEQUENTIAL loop is a
measurement of this device's fsync (~13 ms/fork, so 10^6 would be ~4 hours) rather than
of the runtime. The `stmt ms` column re-measures the WHOLE statement through the parser
at each checkpoint, so the gap the shortcut opens is reported rather than assumed.

Every one of these interns a run and installs a Workspace, a name and a capture in
`AgentRuntime::State`, none of which is dropped while the session is open.
