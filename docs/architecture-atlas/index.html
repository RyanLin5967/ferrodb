The decisive distinction

SQL row versions, private workspace state, and COW page versions are different structures. The detailed views below follow each separately.

Actual server concurrency

Eligible reads can run together. Current pgwire statements that write take an exclusive catalog gate and drain readers; multiple agents do not imply simultaneously executing SQL writers.

Node explanations

CLI or PostgreSQL client

The CLI and PostgreSQL-wire example share execution components. A session separately tracks an ordinary transaction and an agent branch. PostgreSQL wire compatibility is a protocol surface, not the PostgreSQL storage engine.

Parse and route

The scanner/parser creates statements. Execution dispatch routes agent commands and branch-session DML to AgentRuntime. Ordinary SELECT is bound and planned; ordinary DML uses dedicated operators.

Ordinary SQL execution

The ordinary path reads and writes heap rows with MVCC visibility. Its primary and secondary B+ trees locate row versions; they are separate from the branch COW tree.

AgentRuntime

An agent session lives across statements. It stages changes in a private workspace, captures typed effects, and mirrors row state to its branch COW pages.

Shared SQL heap

Normal SQL rows remain in the ordinary heap. The trunk COW tree is not an alternative authoritative copy of those tables.

Merge admission

SQL MERGE reads the workspace and its in-memory effect frame, evaluates against the current heap, then applies accepted rows in one ordinary WAL transaction. It does not replace the trunk COW root.

Private workspace — RAM

Persistent maps preserve inherited private state. Actual SQL reads combine current committed heap rows with these maps. Live merge input comes from Workspace.frame; the durable TEL is not replayed into this workspace on reopen.

Main database pages

Heap/index allocation is below the persisted arena floor; branch arena allocation is above it. Both use the main database buffer pool and file. The branch catalog uses a different file and pool.

Logs and metadata

WAL supports ordinary row recovery. TEL stores typed intent when a durable implementation is configured. Branch records identify roots, ownership, generations and leases. Their separate durability boundaries matter.

Branch COW pages

These are real page-backed trees with their own roots. They support COW isolation, diff and reclamation, but normal branch SQL reads still use the workspace overlay.

02

From SQL to a physical row

This is the ordinary SQL path. Primary and secondary indexes lead to heap row locations, not branch roots.

Two kinds of synchronization

MVCC decides logical visibility. Page latches protect physical tree structure during traversal/splits. Buffer pinning protects residency. None of these substitutes for the others.

Index maintenance is distinct

Ordinary indexes mutate in place. Deletes retain entries and scans filter stale candidates. Heap recovery is followed by index rebuilding in the CLI; this is not per-index-operation WAL redo.

Node explanations

Bind SELECT

Name/type binding builds expressions with column positions and a logical SELECT plan. DDL and ordinary DML are not all passed through this same logical-plan pipeline.

Optimize → lower

The optimizer can choose table or index scans and hash or nested-loop joins. Inner joins can be reordered; supported left joins preserve their semantics. Lowering produces executor operators.

Execute with ReadView

Operators share one read view for the statement. An ordinary explicit transaction supplies its retained snapshot; autocommit statements obtain a current snapshot.

Secondary B+ tree

The secondary index stores pairs so duplicate column values remain distinguishable. It resolves the primary key through the primary index before fetching the heap row.

Primary B+ tree

The index root cell is shared by handles so a root split is visible to later lookups. Internal pages route by separator keys; linked leaf pages support ordered scans.

Heap page and slot

A physical RecordId identifies a slot in a heap page. The current version may not be visible to this reader; its previous-version pointer leads into the time-travel heap. Index candidates are rechecked against visible row values.

Sequential scan

Without a useful index, the heap scanner walks table page directories and row slots. MVCC visibility still applies; a scan is not permission to expose uncommitted rows.

Buffer pool — RAM

Pinning prevents eviction while a caller uses a frame. Dirty pages need writeback. ARC replacement tracks recency/frequency; staged touch batching and optimistic read shadows are cache/concurrency techniques, not branch COW.

Disk manager

DiskManager maps page IDs to blocks and manages allocation bitmaps. The main database reserves disjoint heap/index and branch arena regions. WAL must be durable through a dirty heap page's LSN before that page is written.

Node explanations

Reader snapshot

A snapshot includes a creator transaction when its ID is below high_water and it was not active at capture. ReadView also treats its own transaction ID as visible. The begin_ts/end_ts field names contain transaction IDs, not wall-clock times.

Current row: value 15

An UPDATE puts the prior row version into the time-travel heap and makes the new row the head. A larger tuple can move to a new physical location; indexes are updated accordingly.

Older row: value 10

The old copy's end transaction is the updating transaction B. A reader whose snapshot excludes B can still see the old copy if it includes A. Versions live as tuples, not full snapshots of every page.

Reader started before B

For a transaction started before B, the new head is invisible. Following prev reaches the version created by A; B does not count as a visible ending transaction, so value 10 remains visible.

Version visibility test

ReadView first checks creation visibility, then whether a nonzero end_ts is visible. If a head fails, resolve_visibility follows the previous-version chain. A transaction also sees its own changes.

Reader started after B

After commit, a new snapshot includes B. The head is visible; the old version is ended by a transaction this reader includes. An already open ordinary transaction keeps its original snapshot.

04

Fork and shadow paging, with real pointer roles

Illustrative IDs. This is the branch COW tree, not a frozen copy of every ordinary SQL table.

Select a node to explore
↳ Select any diagram node for its explanation and source evidence. Keyboard: Tab, then Enter.

RAM shares a second structure

Fork also clones roots of immutable workspace maps. These are balanced binary trees in RAM, not disk B+ tree pages. Map edits copy their path; later parent-private edits stay isolated.

Exclusively owned pages can change in place

The writer must own the page and its birth epoch must meet the privacy barrier, which includes the latest live child fork. Splits or boundary repairs can allocate extra pages.

Avoiding a full data copy is not zero cost

Fork still performs catalog, synchronization and durability work. Branches also add effect capture, workspace and page-management costs; no cheaper-than-transactions claim is made.

Two branch records

Fork creates child metadata with a new identity/generation/lease and the parent's root ID. Sharing this number makes the existing COW tree reachable without copying all data.

Child record

Only this child's record receives the new COW root. The branch catalog also has its own B+ tree root; that is a different ID in a different tree.

Page 30: copy

The root needs a copy because its child pointer changes. A deeper tree may need affected shared ancestors copied along the path; unchanged subtrees remain shared.

Bounded copying is the benefit

Node explanations

Descend internal nodes

CowTree::get receives a root ID and key, not a branch ancestry chain. ArenaPageStore fetches the page through the main buffer pool and verifies its COW checksum.

Read result

Pins keep a buffer frame resident during access. A cache miss loads the page; a cache hit reuses the existing frame. The branch tree read is separate from SQL's heap-plus-workspace overlay.

Need a writable page

Private iff the writer owns the page's arena and birth_epoch >= max(branch fork epoch, latest live child fork epoch). The stored private flag is not a substitute for these checks.

Shared: shadow page

Inherited pages are not the child's property to retire. Replaced pages owned by this writer are retired only when the operation commits, and descendant pins may still defer reuse.

Edit / split leaf

Leaf boundaries use key hashes and entry sizes with page-capacity bounds. Some updates/deletes repair chunk boundaries, so the simple two-page copy example intentionally excludes splits and boundary repair.

Relink ancestors

Ancestors need edits when child pointers or separator keys change. Shared ancestors copy; private ones can update in place. Relinking can stop when nothing above changes, or create a new root after a split.

Operation rollback journal

On a tree error, restore the pages mutated in place. Some newly allocated unreachable pages may remain until branch reclamation. This journal handles one tree operation, not disk power loss or a multi-store SQL transaction.

Return / record resulting root

AgentRuntime::put_row records a new root only if CowTree returned a different ID. TableBranchCatalog persists its own metadata separately; root publication alone does not imply atomic persistence of all COW data pages.

06

Inside the pages: three layouts, three purposes

Page IDs locate blocks. Root IDs choose starting blocks. Child IDs route through trees. Row locations select heap slots.

Select a node to explore
↳ Select any diagram node for its explanation and source evidence. Keyboard: Tab, then Enter.

Where is the root ID?

A branch record stores its COW root ID in the branch catalog. The catalog has its own separate tree root. Every page does not store the root of its tree.

Where is the page itself?

A buffer-pool hit reuses a RAM frame; a miss reads the requested page from disk. Fork does not load the whole tree. A page must be in memory before it can be edited.

Node explanations

COW header — 24 bytes

Offsets: birth epoch 0–7; arena ID 8–11; checksum 12–15; type 16; flags 17; reserved 18–23. No branch root ID or list of child IDs lives here.

COW internal payload

A slotted node holds variable-size cells. Leftmost child has its own payload field; other child IDs accompany separator keys. Root is a role: a small tree can have a leaf as its root.

COW leaf payload

PagedRows keys concatenate table_id:u32 and row_id:u64 in big-endian order. Values encode typed row values. Ordered scans use an ancestor stack rather than leaf sibling links.

Ordinary index header

Ordinary internal header: 19 bytes. Ordinary leaf header: 27 bytes, including next/prev leaf IDs. The ordinary checksum field is serialized but is not verified COW-style CRC protection. This differs from the COW format.

Ordinary internal payload

Another B+ tree, with pages updated in place under physical synchronization. Shared root cells make splits visible to other index handles.

Ordinary index leaf

Ordinary leaves have sibling links for ordered scans. They locate heap rows rather than hold branch-private encoded rows.

Heap page header

Heap pages use a 23-byte header and 4-byte slot entries. The ordinary checksum field does not imply verified COW-style CRC protection. This is neither the COW node nor the ordinary index node format.

Slot directory

RecordId is physical (page_id, slot_num). Slot offsets locate tuple bytes. It is distinct from the logical row ID used in agent merging.

Tuple / version header

Fixed 24-byte version prefix: begin 8, end 8, previous page 4, previous slot 2, reserved 2. Null bitmap and typed values follow. Current agent row identity is derived from the primary key, not an independent immutable surrogate.

07

What an agent actually reads and writes

Workspace state drives branch SQL. Its frame drives live SQL merge; the appended effect log is a separate representation.

Select a node to explore
↳ Select any diagram node for its explanation and source evidence. Keyboard: Tab, then Enter.

A branch spans statements

A branch retains private proposals until merge or abandonment. Ordinary transaction IDs, effect-frame IDs, branch IDs and generations have different meanings.

Read validation is partial

Exact point reads can detect later agent-published versions. Predicate summaries do not supply complete phantom validation; ordinary writes do not all update this same version map.

Three representations are not one commit

Workspace, TEL and COW mirror are staged in sequence. The per-tree rollback journal does not make the full sequence atomic or restore unfinished sessions after restart.

Node explanations

Current committed heap

The base scan uses read_snapshot_cached with txn_id 0 for each call. A branch does not freeze committed tables at fork.

Combine by logical key

Private inserts add rows. Predicates apply to private after-images too, allowing an edited row to enter or leave the result.

Agent-visible result

Explicit reads capture point-version references or predicate summaries. This AgentRuntime SELECT path refuses general joins.

Compute proposed edit

Recognized same-column + literal or - literal becomes Add(delta). Other expressions can become Assign(evaluated value), including some mathematically equivalent forms.

Validate whole statement

Policy/escrow preflight occurs before row staging. Ordinary SQL outside the agent path bypasses these branch controls.

Stage private workspace

base_rows retains the row's first-touch witness, rows retains latest private state, and frame collects typed effects/guards. fork_seq helps find intervening published operations.

Input to SQL MERGE

Live merge reads runtime state. Reopening the durable effect log does not rebuild the SQL workspaces or admission history.

Append / extend TEL

Durable TEL extends frames and deduplicates identical retries. The pgserver example instead uses a memory effect log. This is not physical recovery WAL.

Mirror row to COW pages

The order is workspace staging, TEL append, then page mirroring. A later I/O failure is not rolled back as one transaction across all stores.

08

Merge means reconciliation, then publication

The live SQL merge uses operation intent, current target rows and checks. It does not replace the trunk COW root.

Select a node to explore
↳ Select any diagram node for its explanation and source evidence. Keyboard: Tab, then Enter.

Arithmetic example

Start at qty 20. A captures Add(−5); B captures Add(−3). Merge A → 15; merge B applies −3 to current 15 → 12. Use point UPDATEs without a prior stale explicit SELECT; additional checks can still refuse a merge.

Precondition versus postcondition

Two −12 withdrawals from 20: WHERE qty >= 12 rejects the second at current qty 8. WHERE qty >= 0 allows it and can produce −4. An explicit postcondition would test the proposed final value.

What is not atomic together

DDL, the row transaction, provenance/history recording and branch sealing are distinct stages. Frame retry deduplication does not establish exactly-once whole-merge retries after a crash.

Node explanations

Branch proposal — RAM

Workspace.frame supplies branch intent. First-touch witnesses and recorded target operations since fork_seq provide context. An ordinary SQL change without an agent operation can be treated as an opaque Assign based on its changed value.

Current target state

The evaluator reads target rows and applied-operation history. It records a fingerprint so publication can refuse an evaluation whose involved tables or tracked premises moved afterward.

Resolve changed cells

No conflicting target effect: clean. Compatible Add/Add, Min/Min or Max/Max: compose. Equal Assign values converge. Different assignments default to Conflict; explicit LWW is incoming-merge-wins and reports discarded effects.

Check admission

Guards check the target before this branch's effects. Assertions check proposed results, but ordinary MERGE supplies none; SIMULATE supplies declared assertions. Exact read checking is limited to tracked runtime versions; predicate-only reads are not automatically quarantined.

No publish

Conflict leaves the branch available for correction. A failing admission gate in production MERGE quarantines the branch. Neither path applies the proposed row batch.

Recheck and preflight

Table counters catch changes between evaluation and publication. This check is different from validating every read made throughout the branch lifetime. Whole-plan preflight prevents known shape/constraint refusals from partially applying schema plans.

Apply schema edits first

Schema work runs before the row transaction. An unexpected I/O failure can leave schema effects even when row publication does not complete; the lifecycle is not a single crash-atomic operation.

One ordinary transaction

All accepted row writes share one TxnManager transaction. This is the tested atomic row batch. Row publication uses ordinary heap/MVCC/WAL rather than making a branch root the shared table root.

Record published history

Applied-operation history and logical row authorship are recorded after commit; physical version-author stamps can be written during row application. These separate provenance writes are not covered by the row WAL atomicity. Sealing then reclaims or retires branch state. A later failure cannot retroactively undo a committed row transaction.

09

WAL, commit, crash recovery

For ordinary heap transactions, durable log records permit table pages to be written later. Log order matters.

Select a node to explore
↳ Select any diagram node for its explanation and source evidence. Keyboard: Tab, then Enter.

Checkpoint shortens recovery

With no active transactions, checkpoint flushes WAL, flushes pages, syncs the database, then truncates eligible WAL and redeclares schema/run state. Retention pins can prevent discarding consumer-needed history.

What the crash test proves

The focused merge test kills a process mid-row-publication and checks all-before or all-after rows. It does not simulate loss of the operating system page cache during machine power failure.

COW has a different local rollback tool

CowTree WriteJournal restores in-place pages after one tree-operation error and delays retirement. It is not this WAL transaction and does not make all branch sidecars crash-atomic.

Node explanations

Ordinary row change

Heap insert/delete/update routines append records and update pages with the corresponding log position. This flow does not mean every schema, index, allocator or COW page mutation is journaled identically.

COMMIT

TxnManager flushes through the commit LSN before reporting success. It then records transaction end and removes the transaction from the active set. Committing does not require every dirty table page to have reached disk.

Durable WAL bytes

WAL uses ordered records with lengths/checksums and a flushed position. The flush path keeps ordering under synchronization; a higher durable watermark must not skip earlier unsynced records.

Later page write

The buffer pool's WAL gate runs before dirty-page flush/eviction. It recognizes ordinary page LSN formats; it is not a universal journal for separate branch metadata and COW pages.

On restart: scan WAL

Recovery scans valid records, initializes transaction ID state, and reconstructs which transactions committed or ended. A torn tail is different from complete transaction recovery.

Redo heap changes

The page LSN makes physical redo repeatable. Redo reconstructs logged history, including work that may later be undone if its transaction did not commit.

Undo unfinished work

Abort/recovery writes CLRs with undo-next pointers so a second crash can continue undo rather than blindly applying the same inverse twice.

Repair and reopen

CLI calls rebuild_indexes and checkpoint after recovery. The pgserver example opens after recover but does not run that same rebuilding block. This entrypoint difference is explicit in the next view.

Node explanations

Main database file: <db>

The main buffer pool caches both regions. Ordinary allocation is below a persisted arena floor; ArenaPageStore owns extents above it. The default new-database headroom is 32,736 ordinary pages, a real growth bound.

<db>.branchcat

TableBranchCatalog stages indexed record changes and group-commits its own pool/file. Its catalog root and each stored branch root are separate concepts. Catalog fsync does not itself flush the main pool's COW data pages.

<db>.arena

This allocator checkpoint/tail records the arena floor, extents, ownership and pending frees. COW row bytes remain in the main database file. Reopen avoids reissuing already-owned extents.

<db>.tel — CLI

The CLI constructs DurableEffectLog. The PostgreSQL-wire example constructs MemEffectLog. Replayed frames can feed a separate effect merger; they do not reconstruct the live SQL Workspace.

<db>.provenance — CLI

The CLI attaches DurableProvenanceStore. The server example leaves the runtime's default memory store. Provenance append durability is separate from row WAL commit.

Startup order

DbLock excludes a second process writing the same database. Ordinary catalog allocation must precede choosing the arena floor. Reopen uses the stored floor; it does not guess a new boundary over existing extents. CLI additionally rebuilds ordinary indexes after recovery.

Reattach storage

A missing or invalid recorded root is refused rather than silently replaced. LeaseThread resumes interrupted reaps. CLI effect/provenance replay restores those stores, not all runtime maps.

Fresh runtime memory

reopen_with_storage constructs State::default. Branch names, workspaces, applied-operation history, merge records, read dependencies and escrow are not rehydrated into an unfinished SQL session. Durable roots alone cannot make it resumable.

The cleanup rule preserves descendants that might still reach old pages. Epoch, lease and generation are different clocks/identities.

Epoch

Logical ordering of page births, forks and frees. Also participates in deciding whether a branch-owned page is private enough to edit in place.

Lease

Standalone: wall-clock deadline for abandoned work; clustered components use replicated time. A background scan and cleanup do the actual reclaim; this is separate from MVCC snapshot visibility.

Generation

Identity fence for recycled branch IDs. Same numeric slot with a different generation means a different branch. Branch GC does not vacuum ordinary heap row versions.

Node explanations

Branch is finished

The default agent lease is 15 minutes; the default background scan is every 30 seconds. Expiry makes cleanup eligible rather than implying exact-deadline deletion. The trunk cannot be reaped.

Persist Reaping state

Persisting an intermediate lifecycle state allows a later startup to resume cleanup after interruption. A stale handle cannot act on a different branch occupying the same recycled ID slot.

Any live children?

The catalog indexes parent/child relationships and child fork epochs. A reaped intermediate ancestor with a live descendant retains its lineage link, preserving protection for grandparent pages.

Childless branch

An arena is a contiguous extent owned by one branch; extents grow geometrically from 1 to 256 pages, then stay capped. A branch can own several arenas. Bulk reclaim is safe when no descendant needs those private pages.

Shared history remains

A page cannot be reused while a live child fork epoch falls in [page birth, logical free). Protection is conservative and indexed by lineage, not a count stored on every page.

Example: page lifetime

5 lies in [3,9), so the child may still reach the old page even though its parent no longer uses it. These numbers are logical ordering epochs, not seconds or transaction IDs.

Persist Reaped state

Reaped slots remain unavailable while live descendants still require them. Generation fencing prevents an old BranchId handle from accidentally reading/writing a new branch after ID reuse. Parent links detach only when descendant pins can be released safely.

Drain pending frees

When the last relevant child disappears, cleanup revisits deferred frees and can cascade upward through reaped ancestors. Startup also resumes interrupted reaps and sweeps orphaned extents.

Arena allocator state

Page payloads are in the main database; ownership/allocation metadata is in the allocator sidecar. Persisted allocation avoids giving a page already owned by one branch to another after reopen.

Node explanations

SIMULATE / selected effects

SIMULATE forks candidates and runs the same evaluator. Assertions determine legality; equally legal candidates tie and declaration order wins. Cherry-pick selects recorded effects into a workspace. Neither is a second storage engine.

Provenance / revert

Provenance captures run/model/prompt identity and read/write relationships. Revert can halt on downstream dependencies or explicitly cascade inverse operations. It is not a tree-root rewind or one all-cascade atomic transaction.

Physical WAL shipping

The source stops at flushed_lsn. Log shipping alone is not leader election or safe automatic failover. Bare redo does not reproduce the full ordinary catalog; an existing integration test explicitly records that limitation.

Logical CDC feed

An initial MVCC snapshot captures existing rows; pinned WAL and a resume boundary bridge later committed changes. Publication filtering controls emitted rows. CDC is not the branch TEL and does not perform branch merging.

Separate consensus components

The consensus state machine and driver coordinate replicated commands and membership. Normal CLI/pgserver do not construct this coordinator. Consensus log round numbers are not local WAL byte offsets.

ClusterAgents coordinator

A merge proposal is based on an applied round, may require re-evaluation if the base moved, and publishes locally after its metadata decision applies. This is a library/test path, not the normal SQL server path.

Distribution boundary

The documented failure window can leave metadata saying merged while row WAL has not arrived. There is no transparent failover for an unfinished node-local branch. No end-to-end distributed SQL atomicity is claimed here.

A–Z

Glossary & scope

Keep the mechanisms distinct.

Page
A 4 KB block addressed by a page ID. Its format depends on what it stores.
Page ID
A numeric block address, not a memory pointer or a content hash.
Root page ID
The starting page for a tree. A branch stores this in its branch record.
Internal / leaf
An internal tree node routes to children; a leaf holds the tree's key/value entries.
Separator key
A boundary used to choose which child subtree can contain a search key.
Header / payload
The format's metadata prefix versus the node or tuple data following it.
RecordId
Physical ordinary row location: page ID plus slot number.
Logical row ID
Identity used to match agent changes; currently derived from primary-key values.
Heap
Pages containing ordinary table tuples, organized through page directories.
Buffer pool
RAM cache of disk pages. Pins prevent eviction; locks protect accesses to bytes.
Latch
Short-lived physical synchronization for page/tree operations; distinct from transaction visibility.
MVCC
Multiple row versions plus a rule choosing which version a reader sees.
Snapshot
Transaction-ID boundary and active set defining visibility, not a complete copied database.
Version chain
Previous-version pointers linking a current tuple to older tuples.
COW / shadow paging
Share existing pages; copy pages when an edit would otherwise change shared state.
Workspace
RAM maps of private row state, before-images, effects, schema edits and related task state.
Persistent map
Immutable, structurally shared map in RAM. Persistent here does not mean saved to disk.
Arena
A contiguous page extent owned by a branch; a branch can own multiple extents.
Epoch
Logical order used for sharing and reclamation. Not elapsed time or MVCC transaction identity.
Lease
Deadline after which background cleanup can retire abandoned branch work.
Generation
Version of a recycled branch identity slot, used to reject stale handles.
TEL / effect frame
Typed operation intent and guards for a task. Separate from physical recovery WAL.
WAL
Write-ahead log: recovery information is made durable before associated dirty heap pages are written.
LSN
WAL position; page LSNs help avoid replaying the same physical update twice.
CLR
Compensation log record describing undo progress so recovery can continue after another crash.
Guard / assertion
Guard: precondition on the target before effects. Assertion: condition on proposed results.
Commuting effects
Supported operations whose combination can preserve both intents; checks can still reject the result.
Fingerprint
Evidence of the evaluated base, checked again before publishing; not a full serializability proof.
Quarantine
Hold an agent branch for inspection after an admission gate refuses publication.
Checkpoint
Coordinate durable state to reduce replay history; retention rules may prevent log truncation.
CDC
Committed row-change feed decoded from WAL, optionally bootstrapped with a snapshot.
Consensus round
Position in the replicated command order, distinct from the local WAL byte LSN.
